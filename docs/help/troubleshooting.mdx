---
title: Troubleshooting
description: Fix thumbnail generation, playback, cache, and deletion issues in VideoCull.
---

Most issues are either stale thumbnails, incomplete metadata, or media compatibility problems. Start with targeted thumbnail regeneration or a rescan. Treat full cache clearing as a last resort because it resets cached review progress.

<AccordionGroup>
  <Accordion title="Thumbnails are not generating or are stuck">
    <Steps>
      <Step title="Check that the folder actually contains videos">
        VideoCull ignores non-video files.
      </Step>
      <Step title="Regenerate affected thumbnails">
        `Shift`-click in the grid to select the affected videos, then choose **Thumbs** in the batch bar. This preserves their decisions and other metadata.
      </Step>
      <Step title="Disable hardware acceleration">
        Some GPU driver setups behave badly with FFmpeg hardware decoding.
      </Step>
      <Step title="Reduce parallel work">
        Lower **Parallel FFmpeg processes** and, if needed, enable **Limit each FFmpeg process to 1 CPU thread**.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Video durations are blank or show as 0">
    Blank or zero durations usually mean the cache was written before duration data was extracted, or that a previous scan was interrupted.

    <Steps>
      <Step title="Rescan the folder">
        Press `F5` to rescan so FFprobe can repopulate the missing duration data.
      </Step>
      <Step title="Clear cache only as a last resort">
        If metadata remains corrupted and saved progress can be discarded, use **Clear cache and reload**. The confirmation warns that cached manual decisions will be lost.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="VideoCull is blocked or does not start">
    <Tabs>
      <Tab title="Windows">
        SmartScreen can warn on launch with the direct installer because it is not code-signed yet. The Microsoft Store edition does not use this installer.

        1. Use the **More info** link on the SmartScreen prompt.
        2. Click **Run anyway**, only if you downloaded the installer from the official [GitHub Releases](https://github.com/StippieDot/VideoCull/releases) page.
      </Tab>
      <Tab title="macOS">
        The macOS app is not signed or notarized yet, so macOS blocks it on first launch.

        1. After moving VideoCull to Applications, run `xattr -cr /Applications/VideoCull.app` in Terminal once.
        2. Or try to open VideoCull, then allow it under **System Settings > Privacy & Security**.
      </Tab>
      <Tab title="Linux">
        AppImages need FUSE 2, which Ubuntu 22.04 and newer do not install by default. Install it with `sudo apt install libfuse2t64`, then run the AppImage again. Make sure the file is executable (`chmod +x`).
      </Tab>
    </Tabs>
  </Accordion>

  <Accordion title="A video does not play in the built-in player">
    The built-in player depends on Chromium codec support. Open the file in your external player when the format or codec is not supported in-app.

    If a format you expect to work still fails, check whether the file opens correctly in your system player first.
  </Accordion>

  <Accordion title="I accidentally sent videos to the Recycle Bin or Trash">
    Restore them from the Recycle Bin or Trash, then rescan in VideoCull so the files appear in the grid again.
  </Accordion>

  <Accordion title="Thumbnail generation uses too much CPU">
    <Steps>
      <Step title="Reduce parallel work">
        Lower **Parallel FFmpeg processes** to keep the machine responsive.
      </Step>
      <Step title="Enable one-thread-per-process mode">
        Turn on **Limit each FFmpeg process to 1 CPU thread**.
      </Step>
      <Step title="Disable hardware acceleration if needed">
        Some GPU drivers behave poorly with FFmpeg hardware acceleration.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Initial scanning is very slow on a cloud-mounted drive">
    Some mounted cloud drives can be much slower to scan than local disks. That has been reproduced on mounted Google Drive setups.

    If possible, copy the files to a local drive first or switch to a less latency-sensitive cache mode before scanning very large remote libraries.
  </Accordion>

  <Accordion title="Recent sessions include folders that are not available">
    An entry on an unplugged drive or offline share stays in the list, marked unavailable, so it opens again once the folder is back. Remove an entry you no longer need with its remove button, or clear the recent list.
  </Accordion>

  <Accordion title="VideoCull says another edition is already running">
    On Windows, the Microsoft Store and direct-download editions share one profile, so VideoCull prevents them from running at the same time.

    Close the other VideoCull window, then start the edition you want to use. If no window is visible, wait for VideoCull to finish closing or end the remaining VideoCull process in Task Manager before trying again.
  </Accordion>

  <Accordion title="VideoCull cannot open the shared profile">
    VideoCull stops before opening a profile whose storage format is invalid or incompatible with the installed edition. This protects settings, decisions, databases, and thumbnails from being changed by an older build.

    Update the older edition before switching again. Do not delete or edit `storage-format.json`, and do not copy one edition's profile over the other. If both editions are current and the message remains, report the exact message on [GitHub](https://github.com/StippieDot/VideoCull/issues).
  </Accordion>

  <Accordion title="Bookmarks or decisions look missing after an update">
    Rescan the folder first so any cache migration can complete. If the data is still missing after that, file a report on [GitHub](https://github.com/StippieDot/VideoCull/issues).
  </Accordion>
</AccordionGroup>
