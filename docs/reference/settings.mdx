Settings are split across the same tabs you see in the app. Most libraries work well with the defaults. Change settings when you have a reason, not because the app offers a knob.

## Before changing defaults

- Leave most defaults alone for your first pass through a library.
- Use the grid to narrow the queue before changing review behavior.
- Touch duplicate settings only when the match quality is clearly too noisy or too strict.
- Treat library, cache, and processing settings as library-scale controls, not per-session tweaks.

<Tip>
  Change one thing at a time, then rescan or rerun the affected workflow. That makes it obvious which setting actually helped.
</Tip>

## Save or discard changes

Settings are edited in a local draft until you choose **Save Preferences**. Closing with the `X` discards unsaved edits.

After saving:

- Theme, interface visibility, card layout, feature toggles, keybindings, mute state, keeper ranking, and protection rules update immediately.
- Cache, scan, thumbnail, metadata, and duplicate-matching changes apply when their next relevant scan or processing run starts.
- Increasing the thumbnail count can prompt you to confirm that existing cached strips need rebuilding.
- Changing cache storage starts a migration choice before the preference is committed.
- Where VideoCull updates itself, changing automatic update checks may require an app restart before startup behavior changes.

VideoCull blocks saving while configurable shortcut conflicts remain. The conflicting keybind fields identify what must be changed.

## General

These settings cover how the app looks, how it starts, and report export.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Theme | Switches the app chrome between Dark and Light mode while keeping video and thumbnail wells neutral. | Use Dark in dim environments and Light when the surrounding room or display is bright. |
| Reopen the last session at startup | Opens the folders that were loaded when VideoCull closed. A session ended with **Close Session** is not reopened. | Turn it on when you usually continue where you left off. |
| Export report | Exports an HTML report for all loaded videos or the current filtered set, grouped by folder and review status. | Use it at the end of a pass or before a destructive cleanup. Export never changes statuses or files. |

The sun or moon button switches theme immediately and saves the choice. It is available on the landing screen and in the sidebar header. ## Grid & review

These settings change how the grid starts, how Review mode plays, and which optional controls are shown. Core status, playback, compatibility, codec badges, global mute, and next-undecided behavior are always part of the normal app workflow.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Default card scale | Sets the starting card size in grid view. | Leave it at `1.0x` unless your monitor or footage needs more or less detail. |
| Default sorting | Controls the first sort field and order for new sessions. | `Name` is the safest default. Use `Date` for chronology, `Size` for storage cleanup, or `Duration` for spotting clips that are too short or too long. |
| Group by folder | Starts the grid grouped by folder instead of one flat list. | Keep it on when folder context matters. Turn it off when you want one global queue. |
| Keep playback controls visible in Review | Prevents the timeline and playback controls from auto-hiding while a video is playing in Review mode. | Leave it off for a cleaner playback view. Turn it on when you want the scrubber to remain available without moving the mouse. |
| Skip length | How far the rewind and forward keys, and the player's `J` and `L`, jump while a video plays in Review: 2, 5, 10, 15 or 30 seconds. | The default of 5 seconds suits most clips. Choose a longer jump for long recordings. |
| 5-star rating | Shows rating controls on video cards and in review mode. | Turn it on only if you actually rate clips. |
| Favorites | Shows the heart toggle and favorites filter. | Turn it on when you need a shortlist across a large session. |

## Library & cache

These settings decide how folders are scanned, where progress lives, how aggressively old data is cleaned up, and what happens to folders after deleting.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Cache storage | Chooses `Centralised`, `Per-drive`, or `Distributed`. | Use `Centralised` unless you need the cache to travel with a drive or folder. |
| Central cache location | Picks the app-controlled cache folder. | Leave it at the default unless the current drive is a bad fit. |
| Per-drive cache location | Picks a cache folder for the currently opened drive. | Use this only when you deliberately want separate per-drive roots. |
| Follow symbolic links (Experimental) | Scans folders and videos that symbolic links point to, also outside the opened folder. | Leave it off unless your library relies on links. See [Sessions and folders](/features/sessions-and-folders). |
| Auto-clean stale cache after scans | Removes stale cache rows, thumbnail folders, and child-folder cache entries that no longer exist on disk. | Leave it off unless you want ongoing housekeeping. |
| Remove empty source folders after delete | Removes parent folders that become empty after deleting videos. | Leave it off unless folder cleanup is part of the job. |

`Distributed` mode creates a hidden `.videocull` folder inside each loaded folder. It is useful for portable libraries, but noisier than centralized cache.

<Tabs>
  <Tab title="Windows">
    On Windows, the link setting is named **Follow symbolic links and junctions (Experimental)** and also follows directory junctions.
  </Tab>
</Tabs>

For migration choices, rebuild behavior, and the difference between cache modes, see [Cache and processing](/reference/cache-and-processing).

## Duplicates

Duplicate detection is best treated as a suggestion engine, not an auto-delete system.

The Duplicates tab is grouped by what you are deciding: when to search, how videos are compared, which changed copies also count, the separate partial clip search, and which copy to keep. **Advanced** is folded away; the defaults suit most libraries.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Enable duplicate detection | Turns on duplicate finding and stores duplicate cache data. Nothing is deleted until you confirm it. | Leave it on if duplicates are a normal part of your workflow. |

### Searching

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Run after each scan | Starts duplicate detection after scanning. | Leave this off unless duplicates are the main job. |
| Videos to search | Chooses between all loaded videos or the current filtered view. | Use the filtered view when you want tighter, more deliberate duplicate passes. |

### Matching

Changes apply to the next search.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Comparison method | Switches between `pHash` and `Visual similarity`. | Start with `pHash`, the default, which produces few false positives. Try visual similarity when known alternate encodes are missed. |
| Similarity | Sets the minimum score needed to group videos as duplicates. A group's displayed score is its weakest match, so every result meets this value. | New installs use one value, `90%`, for both methods; turn on **Separate value per method** to keep one value for pHash and another for visual similarity. Raise it when results are noisy. Lower it when real duplicates are being missed. Any value from `0%` to `100%` works, but unrelated videos start to match below `80%` with pHash and below `90%` with visual similarity. |
| Outline check | Visual similarity only: a sampled frame also needs this pHash similarity, so clips filmed in the same place a moment earlier or later are not reported as copies. Frames that match at 97% or more pass without it, and a copy that starts a moment later is checked after its timing is lined up. | Keep **At least 75% (recommended)**. It is what lets visual similarity use `90%` without grouping different videos. Turn it off only when it keeps apart copies you know are the same. |
| Samples per video | Controls how many sampled frames are compared and how they are scored: by their average, by the weakest sample so every sample must match, or with pHash by the first sample where neither frame is dark. | Keep 3 samples scored by average. Choose **Weakest sample** when results are noisy, or **First sample (pHash)** to find more duplicates at the cost of more false positives. |

### Copies that differ

Each of these can add matches; none removes one. Changes apply to the next search.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Ignore black bars | Also matches copies that only differ by black bars above, below or beside the picture, such as a letterboxed copy of a full-frame video. | Leave it on. Turn it off only when it groups videos you consider different. |
| Compare flipped videos | Also checks horizontally mirrored copies. | Turn it on only when mirrored duplicates are a real possibility. |
| Match partly unreadable videos | Compares a video on the samples that could be read when some sampled positions could not be decoded, so a damaged or cut-off copy can still match a good file. | Leave it on. |
| Double-check near misses | Compares pairs that score up to the chosen number of points below your similarity value again, with frames around each sample, and matches copies that start a moment earlier or later. A pair still has to reach your similarity value. Needs at least 2 samples and does not work with First sample scoring. Visual similarity looks at most 10 points down. The extra frames are read for at most 200 videos per run and kept for later runs. | Keep **Up to 20 points below**. Choose 25 when you use 5 or more samples and still miss shifted copies; turn it off to skip the extra reading. |

### Partial clips

A separate search, started with **Find Partial Clips** in the sidebar, for videos that contain part of another video. See [Partial clips](/features/partial-clips) for how results are found and labelled.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Find partial clips | **By sound** shows **Find Partial Clips** in the sidebar. It reads the sound of every video once and keeps it, about 115 KB per hour of sound; each match is checked with pictures. | Turn it on when your library has excerpts, trimmed versions or compilations of other videos. |
| Minimum shared part | Shown while Find partial clips is on. A pair that shares sound is checked with pictures only when the shared sound covers at least this share of the shorter video (40% by default) or lasts five minutes. Keeps out videos that only share an intro or outro. | Lower it to find shorter shared parts; more pairs are then checked. |
| Common sound limit | Shown while Find partial clips is on. Sound found in more than this many videos (25 by default) counts as an intro, jingle or music and is not searched; the sidebar says in how many videos it was skipped. | Raise it when a clip is reused in many videos; more pairs are then checked. |
| Intros and outros | Shown while Find partial clips is on. Footage at the start or end of a video that the other video lacks, up to this long (10 seconds by default, never more than a tenth of the video), is not reported as missing and does not stop a video counting as **Fully inside**. Only changes how results are labelled, not what is found. | Raise it when studio logos or end credits keep excerpts from counting as fully inside; lower it to see every missing second. |

### Keeping and deleting

Changes update the current results right away.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Protect marked keep videos | Stops already-kept videos from becoming delete suggestions. | Leave it on. |
| Protect skipped videos | Leaves skipped videos out of automatic delete suggestions. | Leave it off when Skip means undecided and should still compete. Turn it on when skipped clips must never be suggested for deletion. |

Suggested keeper priority decides which file is preferred inside a duplicate group.

- Readable everywhere: a copy that could not be read at a sampled moment another copy of the group could read is not preferred.
- Resolution
- Video bitrate
- Duration
- FPS
- File size
- Codec, ranked by the codec preference list under it, collapsed until you open it (AV1, H.265 / HEVC, VP9, H.264, VP8, MPEG-4, MPEG-2, WMV / VC-1 by default). Codecs not in the list tie and the next rule decides. Codec comes after File size by default; move it above Video bitrate and File size if you want a more efficient codec to win over a higher bitrate or larger file.
- Has sound: a copy with an audio track is preferred. A video whose details have not been read yet counts as having sound. It is last by default; move it up if a copy without sound should never be suggested.

Duration ignores differences of up to 2 seconds or 1 percent of the longest copy.

Higher items decide first. Reset the order unless you have a strong reason to prefer a different kind of source file.

**Ignored matches** counts the pairs marked **Not a match**; they stay apart in later duplicate and partial clip searches.

- Leave ignored matches alone if the rule was correct.
- Clear them only after you change matching behavior enough that old ignores are no longer trustworthy.

### Advanced

Folded away by default; open it with **Advanced** at the bottom of the tab.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Sampling window | Chooses which part of each video gets sampled. | Leave it on evenly spaced. Move inward only when intros, outros, or watermarks are skewing results. |
| Length difference | Limits how much two durations may differ and still be compared. | Raise it only when alternate encodes differ slightly in runtime. |
| Max sampling duration | Samples only the first this many seconds of each video. `0` means full length. | Leave it at the default unless very long videos make runs too expensive. |
| Skip blank frames | Ignores sampled frames that are a single flat colour, such as a black screen, a grey card or a fade, which would match any other blank frame. Frames that are mostly black are always ignored. A pair whose remaining frames are too few is not matched. | Leave it on. |
| Samples needed for a match | How many samples must be compared before two videos can match. **Automatic** needs 2, or 1 with one sample or first-sample scoring. A match decided by one sample is marked for checking. | Leave it on Automatic. Choose 1 only to find damaged copies when you use many samples, and check those matches before deleting. |
| Retry failed fingerprints | Reads videos that could not be read in an earlier search again. | Turn it on when a previous run hit processing failures. |
| Checkpoint interval | How often a long search saves its progress, so a cancel or crash keeps it. `0` saves only at the end. | Change it only for very large duplicate passes. |

## Processing

Processing settings affect future scans, thumbnail runs, and metadata work. They do not retroactively rebuild current thumbnails until you rescan or regenerate them.

| Setting | What it does | Suggested default use |
| --- | --- | --- |
| Thumbnails per video | Chooses `1`, `2`, `4`, `6`, or `9` frames per video. | `6` is a good default. Raise it only when the strip is not giving enough context. |
| Skip intro blackframes (delay) | Delays the first thumbnail to avoid fade-ins or blank starts. | Keep the default `3s` unless your clips start cleanly or need a longer skip. |
| Parallel FFmpeg processes | Caps how many FFmpeg jobs run at once, or uses auto mode. The sound search of Find Partial Clips uses as many processor cores, up to the number the computer has. | Leave it on `Auto` unless the machine becomes unresponsive. |
| Limit each FFmpeg process to 1 CPU thread | Uses more small FFmpeg processes instead of fewer multi-threaded ones. | Leave it on. The app marks it as recommended for a reason. |
| Enable hardware acceleration (beta) | Tries to route decoding through the GPU. It is off by default. Duplicate fingerprints always use the CPU. | Leave it off unless CPU decode is the bottleneck and your footage behaves well with it. |
| Keep the PC awake while processing | Stops the computer from going to sleep on its own while folders are scanned, video info and thumbnails are generated, or duplicates are fingerprinted. Choosing Sleep yourself still works, the screen can still turn off, and paused processing does not keep the PC awake. | Leave it on, especially for long runs on large folders. |

<Tabs>
  <Tab title="Windows">
    Hardware acceleration uses D3D11 or DXVA.
  </Tab>
  <Tab title="macOS">
    Hardware acceleration uses VideoToolbox.
  </Tab>
  <Tab title="Linux">
    Hardware acceleration uses VAAPI or NVDEC. On Fedora, install the graphics drivers from RPM Fusion first: Fedora's standard drivers leave out H.264 and HEVC, so those videos decode in software.
  </Tab>
</Tabs>

## Keyboard shortcuts

Keyboard shortcuts are for review-mode and preview behavior, not for system-level app actions.

- Review mode shortcuts are grouped into Navigation, Decisions, Playback, and While playing. Global shortcuts have their own box.
- Click a keybind field to record a new shortcut.
- `Esc` cancels recording.
- **Reset defaults** restores the built-in review bindings.

System shortcuts like `Ctrl+O`, `F5`, `Ctrl+Backspace`, and `Shift+Esc` are fixed and are not rebound here. If two configurable keybinds conflict, fix the conflict before saving.

## Updates

The Updates tab reflects how your edition is distributed.

<Tabs>
  <Tab title="Windows">
    The Microsoft Store edition shows the installed version and confirms that updates are managed and installed by Microsoft Store. GitHub update controls and the automatic-update setting are not shown. The direct-download edition has the update controls described below.
  </Tab>
  <Tab title="macOS">
    The tab shows the installed version and says that this version does not update itself yet. Download new versions from GitHub Releases. There are no update controls.
  </Tab>
  <Tab title="Linux">
    The `.deb`, `.rpm`, and AppImage builds have the update controls described below. The `.deb` and `.rpm` packages ask for your password to install an update.
  </Tab>
</Tabs>

<Tabs>
  <Tab title="Windows and Linux">
    | Setting | What it does | Suggested default use |
    | --- | --- | --- |
    | Check for updates | Manually checks for a new release. | Use it when you want to pull a release now instead of waiting. |
    | Automatically check for updates on startup | Checks at launch and downloads in the background. | Leave it on unless you want fully manual update control. |

    VideoCull always notifies you before anything installs. When an update is ready, choose one of these actions:

    - **Update now** closes VideoCull, installs the update, and opens the updated version.
    - **Install on exit** keeps the app open and installs only when you later close it.
    - **Ask me later** dismisses the prompt for the current session and asks again after the next launch.
  </Tab>
</Tabs>
